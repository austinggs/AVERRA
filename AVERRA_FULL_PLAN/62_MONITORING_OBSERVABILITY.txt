PURPOSE
Defines logs, metrics, traces, alerts, and business-operational monitoring.

NORMATIVE LANGUAGE
The terms MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, and MAY are used as engineering requirements.

TECHNICAL SIGNALS
Latency, error rate, saturation, queue depth, DB health, cache health, worker failures, frontend errors, game load/performance.

FINANCIAL SIGNALS
Reward creation rate, pending liability, available liability, withdrawal queue age, payout failures, reconciliation variance, reserve coverage, duplicate/replay events.

DAIMO SIGNALS
Hurry request volume, queue age, session creation failures, sessions nearing expiry, expired sessions, payment-detection delay, settlement failures, payout-provider failures.

ALERTING
Page only actionable incidents; route lower-severity anomalies to dashboards/tickets.

TRACING
Correlation IDs across API → DB/event/job → provider callback → ledger/payment state.

IMPLEMENTATION NOTES
This document is a planning/source-of-truth artifact. Concrete library choices, exact endpoint names, provider-specific payload formats, and deployment values may be finalized during implementation only when they preserve the stated invariants and pass the defined verification gates.

RELATED DOCUMENTS
See 71_ARCHITECTURAL_LAWS.md, 82_SOURCE_INDEX.md, and the domain-specific database/API/acceptance documents for cross-system contracts.

REVIEWS / COMMUNITY SIGNALS
Monitor review publication errors, comment creation errors, attachment upload failures, report volume, moderation queue age, notification creation failures, and unusual activity spikes. Track Supabase database/storage/function health and Vercel deployment/runtime errors. Review analytics must remain distinct from financial monitoring.


## V7 Admin Observability
Monitor Admin Portal queues, Edge Function failures, scheduled automation failures, reconciliation exceptions, provider callbacks, and privileged-operation errors.
