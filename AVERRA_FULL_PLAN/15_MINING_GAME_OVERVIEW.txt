PURPOSE
Defines the native Three.js Mining Game as a first-class product subsystem.

NORMATIVE LANGUAGE
The terms MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, and MAY are used as engineering requirements.

GAME IDENTITY
A browser-based 3D virtual mining/industrial management game. It is entertainment/progression software, not cryptocurrency mining.

PLAYER LOOP
Explore/operate site → extract virtual resources → process/store → upgrade machines → expand site → complete missions/events → progress achievements/leaderboards.

FINANCIAL SEPARATION
Virtual ores, fuel, machine levels, energy, XP, and inventory are game state. They do not inherently equal cash. Financial rewards require a Reward Engine rule and funding source.

AUTHORITY
Server authoritative for persistent gameplay state, progression, inventory, energy, mission completion, reward eligibility, and anti-abuse decisions.

SCALABILITY
Content is data-driven to support new zones, machines, resources, missions, and events without rewriting the core.

IMPLEMENTATION NOTES
This document is a planning/source-of-truth artifact. Concrete library choices, exact endpoint names, provider-specific payload formats, and deployment values may be finalized during implementation only when they preserve the stated invariants and pass the defined verification gates.
