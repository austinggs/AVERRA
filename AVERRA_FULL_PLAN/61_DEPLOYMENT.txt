PURPOSE
Defines CI/CD gates and controlled release practices.

NORMATIVE LANGUAGE
The terms MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, and MAY are used as engineering requirements.

PIPELINE
Format/lint → typecheck → unit/component tests → integration/API tests → security checks → build → staging deployment → acceptance checks → approval → production deployment.

DATABASE CHANGES
Migrations are reviewed/tested, backward-compatible where practical, and deployed in controlled order.

PROVIDER CHANGES
Use sandbox/test credentials and non-live endpoints where available; verify callback signing and economics before enabling live traffic.

PAYMENT CHANGES
Manual payout logic and automatic Daimo flows require dedicated test cases and rollback/disable procedures.

RELEASE RECORD
Version, commit, migrations, configuration changes, tests, approver, deployment time, and rollback procedure are recorded.

IMPLEMENTATION NOTES
This document is a planning/source-of-truth artifact. Concrete library choices, exact endpoint names, provider-specific payload formats, and deployment values may be finalized during implementation only when they preserve the stated invariants and pass the defined verification gates.

RELATED DOCUMENTS
See 71_ARCHITECTURAL_LAWS.md, 82_SOURCE_INDEX.md, and the domain-specific database/API/acceptance documents for cross-system contracts.

SUPABASE / VERCEL DEPLOYMENT
Production web deployments target Vercel. Supabase migrations, RLS, storage policies, functions, configuration, and environment bindings are version-controlled and reviewed. Preview/staging deployments must not gain production financial authority merely because they are deployed. Never expose Supabase service-role/secret credentials in Vercel client bundles; privileged secrets remain server-side only.

CURRENT SUPABASE BASELINE NOTE
As of September 30, 2026, Supabase documents changes around public-schema Data API exposure and current Node/SDK support. Exact project/CLI/library versions must be pinned and re-verified during implementation.


## V7 Deployment
Production web deployment targets Vercel. Supabase migrations, Edge Functions, secrets, RLS, and operational configuration are managed separately and securely.
