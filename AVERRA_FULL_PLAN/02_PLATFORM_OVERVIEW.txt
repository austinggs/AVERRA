PURPOSE

NORMATIVE LANGUAGE

CORE EVENT PATH
Provider/native completion → verification → reward calculation → pending ledger entry → settlement/approval → available balance → withdrawal eligibility → payout operation → settlement confirmation → reconciliation.

TRUST BOUNDARIES
Browser/client is untrusted; provider callbacks are externally supplied and must be verified; admin tools are privileged; game server controls persistent game state; payment providers are external dependencies; analytics is downstream telemetry.

AVAILABILITY PRINCIPLE
Provider availability, campaign state, payout provider state, and market eligibility are configuration-driven and can be suspended without deleting historical records.

IMPLEMENTATION NOTES
This document is a planning/source-of-truth artifact. Concrete library choices, exact endpoint names, provider-specific payload formats, and deployment values may be finalized during implementation only when they preserve the stated invariants and pass the defined verification gates.
