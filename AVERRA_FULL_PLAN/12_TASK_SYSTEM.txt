PURPOSE
Defines first-party tasks created and verified by Averra.

NORMATIVE LANGUAGE
The terms MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, and MAY are used as engineering requirements.

TASK MODEL
Task definition, task attempt, completion, verification, event history, reward rule, budget, eligibility, and expiry.

VERIFICATION
Each task type declares its verification mechanism. Client completion claims are evidence only, never sufficient for financial credit unless a server verification rule explicitly says so.

TASK STATES
draft, scheduled, live, paused, expired, archived; attempts/completions have separate lifecycle states.

FUNDING
Rewards come from campaign/advertiser/provider budgets or approved Averra-funded budgets.

ABUSE CONTROLS
Rate limits, repeat-attempt rules, identity/device controls, impossible-time checks, and review queues.

IMPLEMENTATION NOTES
This document is a planning/source-of-truth artifact. Concrete library choices, exact endpoint names, provider-specific payload formats, and deployment values may be finalized during implementation only when they preserve the stated invariants and pass the defined verification gates.
